Decisions settled before dispatch

  • OCaml is in. Reverses the “park OCaml” recommendation. ocaml-code-writer (19,551 B) is absorbed in 5b. Second consequence: OCaml gains adversaries for the first time — §2.4’s ocaml reviewer ✗ tester ✗ architect ✗ row closes the moment the gate cards go language-neutral in 5c.
  • The graph carries no language. code-gan.json’s generate node retargets to code-writer, not to a book. books = [...] and requires.book are not mechanical until three readers exist (5d/5e): lockfile schema accepts books; AXEL pre-flight step 4 reads it; requires.book: true + an explicit books = [] (or a consumer lockfile supplied via env) is a verifier or smoke failure. Absence of the books key on the loops self-pin is not a failure. The empty-array demo lives in the 5e smoke fixture. Multi-book: per-PBI, or stop and ask — not first-listed. Retargeting to rust would force code-gan-<lang>.json forks with identical topology — the duplication PR 3 deleted rust-team-lead to kill.
  • The Rules projection is <book>/RULES.md. One generated file per book: committed (bootstrap copies trees and never runs generators), drift-detectable and gated by review discipline (decision 8), ids fully qualified. Not under references/ — that directory is the extractor’s input, and keeping it How-only makes “the reviewer never sees How” checkable.
  • The contract is universal; the topic set is per book. The contract governs topic references: each carries ## Rules + ## How; ids are append-only; RULES.md is generated. specialization.md and verification.md are contract references — neither heading, extractor skips them, fail-loud does not apply. Same home as the PR 4 exemplar (axel/references/). 19 of 21 catalog skills already carry both. Which topics a book has is the book’s business. Prefixes are a baseline, not a closed set — the extractor accepts unknown prefixes. Sharing RE = errors is nice for humans; enforcing the rust list is how OCaml monads get stuffed into RF.
  • Staged duplication is allowed and time-boxed. 5a and 5b create books while the three writers still exist. The old path stays authoritative through 5b. 5c deletes the superseded writers. 5d moves the consumer disclosure. The pin insulates consumers in between. Do not write “old path authoritative until 5d” in a 5a PR body — a 5c reviewer will treat a correct deletion as a brief violation.
  • Book membership is explicit. A book is a catalog skill directory whose SKILL.md frontmatter carries metadata.book: "true" (quoted; a top-level book: key is outside the agentskills.io frontmatter set — 5a review). extract-rules selects on that marker; verify-skill-refs reads the same one. Not inferred from “any references/ with a ## Rules heading” and not inferred from “a directory containing RULES.md”. diataxis is not a book.
  • Featured set after 5c is ["code-writer", "rust", "code-review", "agent-harness", "skill-evaluator"]. verify-docs asserts featured ⊆ skills. 5c cites this; 5e reconciles the harness must-list; 5g mirrors the landing pills. Product choice, not an agent’s call.
  • There is no CI. Measured: loops and harness have no .github/; skills has one Pages-deploy workflow; this prompt-set PR reports zero check runs. Do not fold a workflow into PR 5. Tags cut after pasted validation. Every gate this stack adds is drift-detectable, gated by review discipline. Write §7 row 5 that way, not “drift-gated”.
